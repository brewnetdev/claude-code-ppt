# SLIDE-RULE 스타일 가이드

정본 구현체: `docs/html/l9-harness-evaluator-slides.html` (89장). 이 문서와 구현체가 어긋나면 구현체가 정답이다.
`assets/template.html`은 그 구현체에서 CSS·JS를 그대로 추출한 스켈레톤 — 항상 템플릿 복사로 시작하고 CSS를 새로 쓰지 않는다.

## 1. 캔버스와 안전 영역

- 슬라이드 1280×720 고정, `#deck`이 화면에 scale-to-fit. 슬라이드 패딩 `46px 66px 80px`.
- **콘텐츠 하한 660px** — 직속 자식의 `offsetTop+offsetHeight`가 660을 넘으면 푸터와 충돌. **우측 한계 1280px**(안전권 1240) — flex row는 컨테이너 폭만 넘쳐도 티가 안 나므로 심층 자식까지 검사해야 한다. 둘 다 `scripts/verify.mjs`가 게이트.
- 넘칠 때 대응 순서: ① 표는 `class="tight"`(패딩 8px) ② 박스 여백·`padding` 축소 ③ 폰트 1단계 축소 ④ 그래도 안 되면 **슬라이드 분할(점진 빌드)**.

## 4. 슬라이드 아키타입 (콘텐츠 유형 → 마크업)

정확한 마크업은 정본 구현체의 해당 장을 열어 복사한다 (괄호 = 정본 슬라이드 번호).

- **A 표지** — 좌 텍스트(kicker/h1/부제) + 우 이미지, `padding-left`로 중앙 균형 (#1)
- **B 소개/목차** — 2컬럼 리스트 (#2) / `.agenda` (#3)
- **C 섹션 타이틀** — `.sec`: 대형 `.cnum` + h1 + 질문형 sub. **챕터마다 독립 장표 필수** (#4)
- **D 용어표** — 챕터 도입마다 `용어(풀 네이밍)/쉬운 설명` 표 + key에 챕터 핵심 한 줄 (#5, 18, 33…)
- **E 비교표** — 지시vs구조(#12), Eval vs 테스트(#59), 안티패턴(#86)
- **F 흐름 다이어그램** — 박스+`.arh` 체인, 게이트는 `✓` 박스 (#7, 47)
- **G 순서도** — **번호 ①②③ 필수**, 분기는 `alab`("③이 아니오면 ↓"), 복귀는 라벨("⑤→② 반복") (#67, 85)
- **H 워터폴** — 실패 축이 2개 이상일 때: 관문 박스 + 우측 "새는 곳" `.box r` 짝 (#84)
- **I 사다리/계단** — `align-items:flex-end` + `margin-bottom` 층계 (#34~36, 74)
- **J 빅넘버 대비** — `.num` 좌우 박스 + `vs` (#51)
- **K 2층/합류 구조** — `.frame` 상하 + 승격 라벨(#41), `.join`(#16, 25)
- **L 결론/Q&A/Thanks** — (#87~89)

## 5. 구성 원칙 (실전에서 검증된 규칙)

1. **챕터 타이틀 분리** — 챕터 제목은 C 아키타입 독립 장표, 내용은 다음 장부터.
2. **점진 빌드 (A→AB→ABC)** — 복잡한 다이어그램·표는 단계 슬라이드로 분할:
   - 미공개 파트는 `.ghost` 점선 박스(`?`)나 `...more` 행으로 **자리를 미리 잡는다**.
   - **픽셀 안정성이 생명**: 이미 공개된 요소는 다음 단계에서 위치·크기·폰트가 1px도 변하면 안 된다. 같은 마진·패딩 유지, 뒤 단계에서 축소 금지. 부제 줄 수가 다른 박스와 짝이면 `&nbsp;<br>&nbsp;`로 높이를 맞춘다. 검증: 두 슬라이드에서 같은 박스의 `offsetLeft/offsetTop` 비교.
   - 표의 점진은 행 추가(위 요소 안 밀림)라 ghost 불필요 — `...more` 행만.
3. **도형화 우선** — 구성 요소·프로세스는 이미지가 아니라 HTML 박스로. 논리 흐름은 순서도(G), 다단 손실은 워터폴(H). 하나의 그림에 서로 다른 의미 축을 섞지 않는다.
4. **문장 규칙** —
   - 발표 구어 수사 금지("시작은 내일 아침" ✗ → "가장 쉬운 첫걸음은 ~부터" ✓).
   - 압축 은유 금지: 슬라이드만 읽고 이해 안 되면 실패. 챕터 참조("3장의 훅")는 내용을 풀어 쓴다.
   - **용어는 원문 우선**: Deterministic·LLM-as-Judge 등 정착된 원어를 어색한 한국어로 의역하지 않는다. 필요하면 `원어 — 한글 설명` 병기.
   - 수치·효과 주장에는 근거(대상·규모·연도)와 메커니즘 한 줄 필수. 링크·복사할 커맨드는 이미지화 금지, `<a>` 텍스트로.
5. **콜아웃 규율** — `.key`는 장당 1개, "이 장에서 가져갈 한 문장"만. 보조는 `.d`로.
6. **anti-slop** — gradient·글로우·컬러 그림자·모션·이모지 불릿·radius>8px 금지. ✓✗△↑↓ 같은 판정 기호는 의미 전달이므로 허용.

## 6. 완성 게이트 (순서 고정)

```bash
# 1) 레이아웃 전수 검사 (+대표 장 스크린샷)
node .claude/skills/slide-rule/scripts/verify.mjs <deck.html> --shots /tmp/shots 1,4,10
# 2) anti-slop 게이트 (0 error 필수 — 판정 기호 emoji warning은 허용)
node .claude/skills/clean-html/scripts/check-slop.mjs <deck.html>
# 3) 대표 장(표지·섹션·점진 빌드 최종장·순서도) 스크린샷 육안 확인
```

점진 빌드를 수정했다면 **해당 빌드의 모든 단계 슬라이드를 함께 수정**했는지 grep으로 확인한다 (한 단계만 고치면 픽셀 안정성이 깨진다).
