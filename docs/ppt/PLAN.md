## 2. 좌표계와 타이포 — 확정 필요한 환산 1건

이 저장소는 **1280×720으로 저작**하고 export에서 1.5× 해 1920×1080을 만든다(`src/scene/constants.ts`). GUIDE는 1920×1080 기준으로 적혀 있으므로 모든 px 값에 **×0.667**을 적용한다.

| GUIDE (@1920) | 저작 좌표 (@1280) |
|---|---|
| 상하좌우 여백 80px | 53px |
| 하단 확보 120px | 80px |
| 도판 최대폭 1600px | 1067px — SVG 원본이 960이라 여유 있음 |

**확정 — 폰트 pt→px 환산.** GUIDE 는 `제목 44pt / 본문 28pt / 코드 22pt / 캡션 18pt` 라고만 적고 DPI 를 밝히지 않아 해석이 둘이었다.

| 해석 | 제목 | 본문 | 코드 | 캡션 |
|---|---|---|---|---|
| PowerPoint 관행 (13.33in 폭) | 59px | 37px | 29px | 24px |
| 웹 96 DPI | 39px | 25px | 20px | 16px |

**콘텐츠가 답을 정했다.** 06-05 의 PromQL 한 줄이 85자다. 본문 폭 1130px 안에 등폭으로 넣으려면 22px 가 상한인데, PowerPoint 관행의 코드 크기(29px)로는 물리적으로 불가능하다. 즉 큰 쪽 해석은 이 패키지의 자산과 양립하지 않는다.

그래서 **96 DPI 해석을 정본으로 삼되, 그 최소치보다 한 단계 크게** 잡았다 — 제목 52 · 본문(lead) 32 · 표 26 · 코드 24 · 캡션 21px. 96 DPI 기준 22pt 하한(19.5px)을 모든 요소가 넘긴다. 실측 값은 `src/canvas/themes/study.css` 상단에 있다.

코드 블록은 여기에 더해 **줄 길이에 따라 자동으로 줄인다**(`assets.py: fit_font_px`). 하한 20px 에 걸리면 줄바꿈 대신 장표를 쪼갠다 — 등폭 코드는 줄바꿈하는 순간 들여쓰기가 무너져 더 안 읽힌다. 현재 걸린 것은 06-05 하나(22px)뿐이다.

## 4. 56 → 77장이 된 이유

MANIFEST 의 56장을 하나도 빼지 않았다. 21장이 는 것은 전부 **자산을 잃지 않고, 발표에 필요한 구조를 갖추기 위해서**다.

**프레임 3장** — `figure_pool` 이 "00장 표지 / 전체 로드맵 장표 / 마무리 장표"를 명시적으로 지목하는데 56장 안에는 그 자리가 없었다. 표지 없는 덱은 쓸 수 없으므로 셋을 만들고 pool 이 지목한 도판을 썼다.

**챕터 타이틀 11장** — 참조 덱(L9 카피)의 `.sec` 구조를 그대로 가져왔다. 큰 챕터 번호 + 장 제목 + 그 장의 장표 목록 미리보기. 11개 장을 오가는 덱에서 지금 어디인지 알려 주는 표지판이다.

**동반 7장** — MANIFEST 가 한 장표에 본문 크기 자산을 둘 배정한 곳이 일곱이다. 한 장에 넣으면 도판이 절반으로 줄어 뒷줄에서 안 읽힌다. GUIDE 가 표에 대해 정한 규칙("행을 줄이지 말고 장표를 쪼갠다")을 그대로 적용했다.

| 원 장표 | 동반 장표가 받은 자산 |
|---|---|
| 02-06 | `ch02-fig1.svg` 계측 구조 |
| 03-04 | `ch03-fig2.svg` 프로브 부팅 루프 |
| 05-03 | `ch05-fig2.svg` Export 옵션 |
| 06-01 | `06-01-up-zero.txt` 타깃 0개 출력 |
| 06-04 | `06-04-labels.txt` 라벨 JSON |
| 06-05 | `ch06-fig2.svg` rate() 해설 |
| 07-05 | `ch07-fig2.svg` pending → firing |

동반 장표의 제목과 말할 것은 MANIFEST 의 **도판 캡션에서** 가져왔다. 새로 지어내지 않았다.

> **자산 커버리지 검사 결과** — MANIFEST 가 배정한 자산 중 덱에 안 실린 것은 표 4개(`03-05` `04-01` `07-03` `10-06`)뿐이다. 이 넷은 `make_figures.py` 가 **읽어서 도판으로 그린다** — 행을 하나도 빠뜨리지 않았으므로 데이터 손실이 아니다. 표와 도판이 다른 숫자를 말하는 사고도 이 구조가 막는다.

### 측정이 잡아낸 것

수치 검사가 실제로 잡은 결함이다. 눈으로는 셋 다 놓쳤을 것들이다.

1. **`.body` 넘침이 제목을 덮었다** — 06-02 카드가 61px 넘쳐 제목·말할 것 위로 겹쳤다. `overflow:hidden` 을 걸어 겹침 대신 잘림으로 바꾸고(잘림은 수치로 잡힌다), 행 수에 따라 밀도를 낮추는 `.dense` 변형을 넣어 해소했다.
2. **PromQL 이 가로로 96px 넘쳤다** — 줄 길이에 맞춰 글꼴을 자동으로 줄이는 `fit_font_px` 로 해결. 이 과정에서 §2 의 폰트 해석도 결정됐다.
3. **덱을 그냥 열면 CSS 가 하나도 안 붙었다** — 스타일을 `study.css`(에디터 전용)에만 뒀기 때문이다. 발표용 단독 실행본을 따로 내면서, 그 셸이 **같은 `study.css` 를 인라인**하도록 만들어 정본을 하나로 유지했다.
4. **같은 CSS 가 한쪽에서만 먹었다** — `data-template` 이 에디터에서는 `.slide` 에, 단독본에서는 `<html>` 에 붙어 앵커 위치가 다르다. `[data-template] .sec` 같은 자손 셀렉터는 에디터에서 자기 자신을 포함할 수 없어 조용히 무시됐다. 변형 클래스를 `.slide-inner` 에도 붙여 셀렉터 하나로 양쪽을 덮었다.
5. **도판·본문이 말할 것을 되풀이했다** — 유사도 검사로 8건 적발(4건은 완전 일치). 도판에서 요약 문장을 걷어내 "한 장표 한 주장"을 지켰다.

## 7. 남은 것 하나

현재 그 장표(`느낌으로는 못 고친다`)는 카디널리티 질의 **코드만** 싣고 출력 없이 성립하도록 만들어 두었다 — 발표에 지장은 없다. 실습 클러스터에서 `topk(10, count by (__name__) ({__name__=~".+"}))` 를 한 번 돌린 결과를 주시면 `snippets/output/09-03-cardinality.txt` 로 넣고 동반 장표를 붙인다.
