4.4.6 · PostgreSQL Setup

PostgreSQL 설치 & 기본 활용 가이드

DB가 연결되지 않은 상태에서 시작합니다. PostgreSQL을 로컬에 설치하고 PATH를 잡은 뒤, 프로젝트용 사용자·데이터베이스를 만들고 psql 기본 명령까지 익힙니다.

기준: PostgreSQL 18 (2026년 초) · 포트 5432 · macOS / Windows / Linux

00시작 전 — 무엇을 설치하나개념

아직 DB가 연결되지 않았기 때문에 먼저 PostgreSQL을 로컬에 설치해 연동해야 합니다. 공식 인스톨러 하나로 아래 구성요소가 함께 설치됩니다.

구성요소역할
PostgreSQL Server실제 데이터베이스 엔진 (기본 포트 5432)
pgAdmin 4브라우저 기반 GUI 관리 도구
Command Line Toolspsql·createdb·pg_dump 등 CLI 도구
이 가이드는 CLI(psql) 중심

pgAdmin으로도 같은 작업을 할 수 있지만, TDD·자동화와 잘 맞는 명령줄(psql)을 기준으로 설명합니다. 그래서 설치 시 Command Line Tools를 반드시 포함하세요.

01다운로드 & 설치쉬움

공식 사이트의 다운로드 페이지에서 OS에 맞는 Installer를 받아 설치합니다. 2026년 초 기준 version 18이 최신입니다.

postgresql.org/download

설치 마법사에서 할 일

  • 구성요소는 기본값 — PostgreSQL Server · pgAdmin 4 · Command Line Tools 선택
  • postgres 슈퍼유저의 비밀번호만 설정 (꼭 기억해 둘 것)
  • 포트는 기본 5432 그대로 사용
Windows — Add PostgreSQL to PATH 반드시 체크

윈도우는 설치 시 Add PostgreSQL to PATH 옵션을 반드시 체크해야 명령창에서 psql을 바로 쓸 수 있습니다. 체크하지 않았다면 시스템 환경 변수에 C:\Program Files\PostgreSQL\18\bin을 수동으로 추가하세요.

02PATH 설정 (OS별)환경 변수

PATH에 PostgreSQL bin 경로가 있어야 어느 폴더에서든 psql이 실행됩니다.

Windows — 수동 추가 (PATH 미체크 시)

시스템 환경 변수 Path에 아래 경로를 추가합니다.

C:\Program Files\PostgreSQL\18\bin

macOS — zsh 사용자

echo 'export PATH="/Library/PostgreSQL/18/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

macOS — bash 사용자

echo 'export PATH="/Library/PostgreSQL/18/bin:$PATH"' >> ~/.bash_profile
source ~/.bash_profile
내 셸이 zsh인지 bash인지 모른다면

echo $0 또는 echo $SHELL로 확인하세요. macOS Catalina(10.15)부터는 기본 셸이 zsh입니다. 설정을 넣은 같은 셸의 파일(.zshrc 또는 .bash_profile)을 source해야 반영됩니다.

03설치 확인 & 접속검증

PATH를 추가한 뒤 버전 확인과 접속을 합니다.

# 설정 확인
psql --version
# psql (PostgreSQL) 18.x

# postgres 슈퍼유저로 접속
psql -U postgres
# 슈퍼유저 비밀번호 입력 — U는 대문자다
-U는 대문자

접속 옵션 -U(User)는 대문자입니다. 접속에 성공하면 프롬프트가 postgres=#로 바뀝니다. 이 프롬프트에서 아래 SQL·메타명령을 입력합니다.

04사용자 & 데이터베이스 생성DCL · DDL

postgres=# 프롬프트에서 프로젝트 전용 사용자와 데이터베이스를 만듭니다.

-- 프로젝트 전용 사용자 생성
CREATE USER tika_user WITH PASSWORD 'tika_password';

-- 개발용 데이터베이스 생성
CREATE DATABASE tika_dev OWNER tika_user;

-- 테스트용 데이터베이스 생성 (별도로 필요한 경우)
CREATE DATABASE tika_test OWNER tika_user;

-- 권한 부여
GRANT ALL PRIVILEGES ON DATABASE tika_dev  TO tika_user;
GRANT ALL PRIVILEGES ON DATABASE tika_test TO tika_user;

-- 생성 확인 (소문자 L)
\l

-- 종료
\q

\l 명령으로 tika_dev·tika_test 데이터베이스가 tika_user를 Owner로 하여 생성됐는지 확인하세요.

테스트 DB를 따로 두는 이유

TDD 사이클에서는 테스트가 수시로 일어나 데이터가 계속 바뀝니다. 개발 데이터를 오염시키지 않도록 tika_test를 분리했습니다. 책의 예제는 dev·production만으로 충분하지만, 실무에서 테스트 데이터 격리가 필요하면 이렇게 추가해 둡니다.

05psql 기본 활용 명령어메타명령

psql 안에서 \(백슬래시)로 시작하는 것은 SQL이 아니라 메타명령입니다. 데이터베이스·테이블 구조를 빠르게 살펴볼 때 씁니다.

명령역할
\l데이터베이스 목록 (소문자 L)
\c tika_dev해당 데이터베이스로 접속 전환 (Connect)
\dt현재 DB의 테이블 목록
\d employees특정 테이블의 컬럼·인덱스 구조
\du사용자(롤) 목록과 권한
\dn스키마 목록
\x확장 출력 토글 (넓은 결과를 세로로)
\?메타명령 도움말
\qpsql 종료 (Quit)
 
# tika_dev 로 접속해서 테이블 구조 살펴보기
psql -U tika_user -d tika_dev

tika_dev=> \dt            -- 테이블 목록
tika_dev=> \d employees   -- employees 구조
tika_dev=> \du            -- 롤·권한 확인
tika_dev=> \q             -- 종료
SQL과 메타명령은 다르다

SELECT ... 같은 SQL은 세미콜론(;)으로 끝나야 실행됩니다. 반면 \dt 같은 메타명령은 세미콜론 없이 Enter만으로 즉시 실행됩니다.

06자주 쓰는 SQL & 백업활용

연결 상태에서 자주 쓰는 SQL

-- 현재 접속 정보 확인
SELECT current_database(), current_user, version();

-- 테이블 생성 → 조회
CREATE TABLE employees (
    id     SERIAL PRIMARY KEY,
    name   VARCHAR(50) NOT NULL,
    salary INTEGER CHECK (salary >= 0)
);
SELECT * FROM employees;

CLI 도구 — DB 생성·백업·복원 (psql 밖에서)

# psql 없이 셸에서 바로 DB 생성/삭제
createdb -U tika_user tika_dev
dropdb   -U tika_user tika_dev

# 백업 (덤프) — 한 DB를 파일로
pg_dump -U tika_user tika_dev > tika_dev_backup.sql

# 복원 — 파일을 DB로 되돌리기
psql -U tika_user -d tika_dev < tika_dev_backup.sql
비밀번호를 매번 안 묻게 하려면

홈 디렉터리의 ~/.pgpass(권한 600) 파일에 host:port:db:user:password 형식으로 저장하면 접속 시 비밀번호 입력을 생략할 수 있습니다. 단, 평문 저장이므로 개인 개발 머신에서만 사용하세요.
