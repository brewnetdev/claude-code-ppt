00SQL 4분류란? · 기준 테이블개념

같은 SQL이라도 테이블 구조를 바꾸는 명령과, 그 안의 데이터를 바꾸는 명령은 동작도 위험도도 다릅니다. 그래서 하는 일에 따라 네 그룹으로 나눠 이해합니다.

분류풀네임한글무엇을 다루나
DDLData Definition Language데이터 정의어구조(테이블·컬럼)
DMLData Manipulation Language데이터 조작어데이터(행)
DQLData Query Language데이터 질의어조회(SELECT)
DCLData Control Language데이터 제어어권한(롤)

기준 테이블 — employees

이 문서의 모든 예제는 아래 직원 테이블 하나를 대상으로 합니다.

컬럼타입설명
idSERIAL (PK)자동 증가 기본키
nameVARCHAR(50)이름 (NOT NULL)
departmentVARCHAR(50)부서
salaryINTEGER급여 (0 이상)
hired_atDATE입사일 (기본값 = 오늘)

01DDL — 구조를 정의한다Data Definition

Data Definition Language(데이터 정의어). 테이블·스키마의 구조 자체를 만들고·바꾸고·지웁니다. PostgreSQL에서 DDL은 실행 즉시 반영되는 성격이 강해 되돌리기가 어렵습니다.

-- 테이블 생성
CREATE TABLE employees (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(50) NOT NULL,
    department  VARCHAR(50),
    salary      INTEGER CHECK (salary >= 0),
    hired_at    DATE DEFAULT CURRENT_DATE
);

-- 컬럼 추가 (구조 변경)
ALTER TABLE employees ADD COLUMN email VARCHAR(100);

-- 테이블 삭제
DROP TABLE employees;
명령어역할
CREATE테이블/객체 생성
ALTER구조 변경 (컬럼 추가·수정·삭제)
DROP테이블/객체 삭제
TRUNCATE데이터 전체 삭제 (구조는 유지 — DDL로 분류)
왜 DDL은 위험한가

DROP·TRUNCATE는 구조·데이터를 통째로 날립니다. DML의 ROLLBACK처럼 간단히 되돌리기 어려우니, 운영 DB에서는 실행 전 한 번 더 확인하세요.

02DML — 데이터를 조작한다Data Manipulation

Data Manipulation Language(데이터 조작어). 테이블 안의 데이터(행)를 넣고·고치고·지웁니다. 트랜잭션으로 묶여 있어 ROLLBACK으로 되돌릴 수 있습니다.

-- 삽입
INSERT INTO employees (name, department, salary)
VALUES ('김철수', '개발', 5000),
       ('이영희', '디자인', 4500),
       ('박민수', '개발', 6000);

-- 수정
UPDATE employees SET salary = 5500 WHERE name = '김철수';

-- 삭제
DELETE FROM employees WHERE name = '박민수';
명령어역할
INSERT행 추가
UPDATE행 값 수정
DELETE행 삭제
WHERE를 빠뜨리지 마세요

UPDATE·DELETE에서 WHERE 절을 빼면 전체 행이 수정·삭제됩니다. 실행 전 SELECT로 대상 행을 먼저 확인하는 습관이 안전합니다.

03DQL — 데이터를 조회한다Data Query

Data Query Language(데이터 질의어). 데이터를 조회만 합니다. 명령은 SELECT 하나이며, DML의 일부로 보기도 합니다.

-- 조건 조회 + 정렬
SELECT name, department, salary
FROM employees
WHERE salary >= 5000
ORDER BY salary DESC;

-- 그룹 집계
SELECT department,
       COUNT(*)         AS 인원,
       AVG(salary)::INT AS 평균급여
FROM employees
GROUP BY department;
요소역할
SELECT조회할 컬럼 지정
WHERE행 필터링 조건
ORDER BY정렬 (ASC/DESC)
GROUP BY그룹핑 후 집계(COUNT·AVG·SUM 등)
읽기 순서 ≠ 쓰는 순서

SQL은 SELECT부터 쓰지만, DB는 FROM → WHERE → GROUP BY → SELECT → ORDER BY 순으로 처리합니다. 그래서 WHERE에는 SELECT에서 만든 별칭(AS 인원)을 쓸 수 없습니다.

04DCL — 권한을 제어한다Data Control

Data Control Language(데이터 제어어). 사용자(롤)에게 권한을 주거나 회수합니다. "누가 무엇을 할 수 있는가"를 다룹니다.

-- 로그인 가능한 롤 생성
CREATE ROLE analyst LOGIN PASSWORD 'pw123';

-- 조회 권한 부여
GRANT SELECT ON employees TO analyst;

-- 권한 회수
REVOKE SELECT ON employees FROM analyst;
명령어역할
GRANT권한 부여
REVOKE권한 회수
TCL은 별개로 보기도 합니다

COMMIT·ROLLBACK은 트랜잭션 제어어(TCL, Transaction Control Language)로 DCL과 구분하기도 합니다. PostgreSQL에서 DML은 트랜잭션 안에서 ROLLBACK으로 되돌릴 수 있습니다.

05한눈에 요약치트시트

분류대상대표 명령어되돌리기
DDL구조(테이블)CREATE ALTER DROP TRUNCATE어려움 (자동 반영)
DML데이터(행)INSERT UPDATE DELETE가능 (ROLLBACK)
DQL조회SELECT해당 없음
DCL권한GRANT REVOKE가능 (ROLLBACK)
한 문장으로 기억하기

구조는 DDL, 행은 DML, 조회는 DQL, 권한은 DCL. 무엇을 대상으로 하는지만 짚으면 어느 그룹인지 바로 나옵니다.
